Play online

    
Two players, one match. The host gets a short code and tells it to a friend, who types it in: the two pages find each other and connect directly, and the game itself never goes through a server. (A free public relay, ntfy.sh, passes the connection details for a moment. If it cannot be reached, you can send two long codes by hand instead.) Both of you need this page open, in the same version.

    

      
      
    

    

      

        
        

        
They press Join a match and type it. The match starts as soon as they have.

      Settings (the host chooses; the guest plays with them)
      

        
        
        
        
      

      
A longer input delay hides a slow connection (your buttons act a moment later) at the price of fewer wrong guesses; a longer rollback window lets the game run further ahead of the other player's buttons before it waits, and costs more work when a guess was wrong.

    

    

      Try a bad connection (for testing; only affects what you send)
      

        
        
        
        
      

      
Your game delays (and drops) what it sends to the other player, so you can see what a worse connection feels like with the settings above, with two windows on one computer. The other player does not need to change anything.

    

    

    

    
Uses a direct connection between the two computers (WebRTC with a public STUN server); the game itself is never relayed through a server, so a few strict networks cannot connect. Your save and options stay out of the match, and the game you are playing now is closed when the match starts (it begins again from the start afterwards). Pause, step and reset are off online. If you switch to another tab or window, the other player's game waits for you.
